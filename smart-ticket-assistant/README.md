# Smart Ticket Assistant

一个 **Manifest V3** Chrome Extension，为 Interpark Ticket 等票务页面提供用户可控的监控、区域匹配和座位选择辅助。它不绕过排队、验证码、登录安全机制或任何支付步骤。

## 功能

- **实时页面监控**：通过 `MutationObserver`、History API 和 `hashchange` 监听页面异步加载与单页跳转，识别等待、购票、座位选择及信息填写状态。
- **区域优先级**：在弹窗中逐行设置优先和备选区域；扩展匹配页面文字、无障碍标签、按钮标题及常见座位/区域控件。
- **座位辅助**：跳过带有“已售、锁定、不可用”等标记的控件，并按指定排数和购买数量挑选候选座位。
- **可选自动步骤**：仅在用户点击“开始监控”并开启此选项后，按带随机延迟的顺序点击区域、座位和安全页面之外的“下一步”。
- **提醒与记录**：发现目标区域时发出 Chrome 通知；将状态、操作和时间保存在 `chrome.storage.local`，可在弹窗查看最近日志。

> 自动化行为依赖目标网站的页面语义与 DOM 标记。请在实际购票前人工确认每个选择；扩展不会填写个人资料、处理验证码、跳过队列或进入/完成支付。

## 安装（开发者模式）

1. 下载或克隆本仓库。
2. 在 Chrome 打开 `chrome://extensions`，右上角开启 **开发者模式**。
3. 点击 **加载已解压的扩展程序**。
4. 选择本目录下的 `smart-ticket-assistant` 文件夹（包含 `manifest.json` 的文件夹）。
5. 固定工具栏中的 **Smart Ticket Assistant** 图标，在票务页面打开弹窗进行配置。

## 使用

1. 输入活动名称（仅作为你的本地记录），以及优先/备选区域；每行一个区域，排序即优先级。
2. 选择数量、排数范围和策略。开启“自动完成”前请确认网站允许你进行这些操作。
3. 点击 **开始监控**。弹窗会显示当前页面状态、已停留时间及目标可用性。
4. 发现位置时，检查页面和通知后由你继续处理登录、排队、身份验证及付款。

## 权限说明

- `storage`：保存配置、日志和历史检测记录到本机浏览器。
- `notifications`：发现匹配目标时显示本地 Chrome 通知。
- `activeTab` 与 `tabs`：让弹窗读取当前标签状态并与内容脚本通讯。
- 内容脚本通过 `<all_urls>` 注入，以适配用户访问的票务域名；它只在检测到票务相关页面内容时工作，不会向任何服务器发送页面或购票数据。

## Interpark 页面优化与调试

第二阶段加入了 Interpark 类页面的常见元素识别：区域控件（如 `SeatGrade`、`SeatArea`、`zone`）、座位控件（如 `Seat`、`data-seat`）及“下一步”控件（如 `btnNext`）。识别结果会用于状态检测及调试显示。

- 在 Popup 开启 **调试模式**，页面右下角会显示当前状态、区域/座位/下一步元素计数与最近操作日志；紫色、绿色、橙色描边分别标记区域、座位和下一步元素。
- 使用 **点击等待时间** 设置每次自动区域点击前的基础等待时间；扩展还会加入一小段随机延迟。
- **自动点击匹配区域** 默认关闭。仅在同时开启它和“开始监控”后，扩展才会点击与优先/备选关键词相符的可用区域。它不会自动点击验证码、队列、个人资料、支付或安全页面。

## 座位评分与人工确认

座位分析器会读取可见座位控件的位置、标签以及不可用状态，过滤“已售/锁定/禁用”的座位，并按选择策略生成 `0–100` 分的推荐结果：

- **靠近舞台**：优先座位图上方（或较小排号）的位置，再以居中程度辅助排序。
- **中间区域**：优先座位图的水平中心，再以靠近舞台程度辅助排序。
- **连座优先**：根据同排的横向间距识别连续可用座位，并为可组成购买数量的连续组增加权重。

推荐座位只会在调试模式中以黄色描边和分数显示，**不会被扩展自动点击**。用户必须在票务页面上人工检查座位图、价格与最终选择后自行确认。

## 真实 Interpark 页面测试（仅识别模式）

1. 在 Chrome 打开 `chrome://extensions`，重新加载本扩展，然后打开你**已正常登录且已通过官方排队流程**的 Interpark 活动页面。
2. 在 Popup 保持 **测试模式：只识别，不点击** 开启，并开启 **调试模式**；不要开启“自动点击匹配区域”。
3. 进入官方座位选择页面后，查看页面右下角的调试面板：它会列出区域按钮、可见可选座位数量、下一步按钮、以及 Canvas/SVG/iframe/图片地图数量。发现目标区域时，扩展会通过 Chrome 通知并尝试使用浏览器 Web Audio API 播放短提示音。
4. 展开“识别 DOM 结构”，核对扩展采集的元素标签、ID、class 和文本是否对应实际区域与座位。Canvas 的颜色摘要会把采样色归为可选、已售或禁用的启发式类别；如显示同源策略错误，表示该画布不可由扩展读取，不能据此推断座位。
5. 黄色描边是评分推荐，**不是已选座位**。请人工核对座位号、票价和官方页面状态后，再由你自行选择和确认。

### 座位图技术说明

扩展会检测 `canvas`、`svg`、`iframe` 和 `map/usemap` 座位图。对可读取的 Canvas，`STASeatMapAnalyzer.captureCanvas(canvas)` 提供本地 PNG 数据 URL 截图接口，`analyzeDocument()` 对像素进行抽样并输出主颜色及启发式可选/已售/禁用分类。它不上传截图或页面数据，也不会绕过跨域 iframe、同源策略、队列、验证码或付款安全限制。

## 扫描与导出

- **开始扫描座位图**：强制刷新 Canvas、SVG、iframe、图片地图与 DOM 座位检测，并更新右下角调试面板。该操作在测试模式下只读取页面信息，绝不点击元素。
- **导出分析结果**：下载本地 JSON，包含页面类型与结构摘要、区域/座位/下一步元素、每个可识别座位的标签、ID、class、坐标、排号、座位号、可用状态和评分，以及 Canvas 尺寸、颜色统计和颜色分类。导出不包含登录凭据、付款数据或截图；Canvas 像素受同源策略限制时会记录错误状态。

## 提醒资源

项目不包含外部音频或图片二进制资源。目标区域被发现时，后台使用 `chrome.notifications` 显示带内嵌 SVG data URL 图标的 Chrome 通知；页面脚本使用 Web Audio API 合成短提示音。若浏览器的自动播放策略禁止该声音，Chrome 通知仍会显示。
